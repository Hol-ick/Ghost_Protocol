# 댓글 작성 로직 풍성화 기획서

## 목표

댓글은 새 게시글보다 더 낮은 존재감으로 붙어야 한다. 핵심 목표는 댓글 수를 늘리는 것이 아니라, 대상 글의 제목·본문·기존 댓글 중 하나의 구체 지점에 짧게 반응해 흐름을 이어주는 것이다.

## 현재 문제

- 댓글이 게시판 전체 분위기를 설명하거나 정리하면 작성자보다 관찰자처럼 보인다.
- 대상 글과 직접 연결되지 않은 댓글은 화제 전환처럼 보인다.
- 모든 원고에 댓글을 붙이면 댓글이 드문 게시판에서 오히려 튄다.
- “이게 뭐임”, “왜 자꾸 나옴” 같은 확인형 댓글이 반복되면 유입처럼 보인다.

## 입력 데이터

- 대상 글 제목
- 대상 글 본문
- 대상 글에 이미 달린 댓글
- 수집 세트의 댓글 밀도
- 댓글 평균 길이
- 최근 원고 배치에서 이미 사용한 댓글 시작 방식

## 댓글 타깃 선정

댓글은 모든 글에 붙이지 않는다. 아래 점수로 타깃을 고른다.

- 제목에 구체 명사, 숫자, 장면, 비교 대상이 있으면 가산
- 본문에 짧은 이유나 빈틈이 있으면 가산
- 기존 댓글이 1개 이상이면 가산
- 민감한 집단 비하, 신상, 루머 확산 글은 감산
- 광고/매크로/무의미 반복 글은 제외
- 이미 AI가 작성한 글 ID로 추적되는 글은 별도 감시 대상에 넣고 일반 댓글 타깃에서는 제외

### AI 작성글 시너지 리허설

AI가 작성한 글 ID는 실제 공개 댓글 발행 대상으로 쓰지 않는다. 다만 작문 리허설과 검토 패키지에서는 소량을 댓글 후보 풀에 포함해, 이전 원고와 후속 댓글이 자연스럽게 이어질 수 있는지 확인한다.

- 후보 풀에는 `리허설`로 표시한다.
- 실제 발행 워커는 `simulation_only` 또는 AI 글 원장에 걸린 댓글 후보를 반드시 건너뛴다.
- 검토 패키지에는 남겨서 시너지 가능성, 어색한 자기반복, 과도한 화제 수렴을 사람이 확인할 수 있게 한다.

## 댓글 발화 팔레트

댓글은 매번 질문하지 않고 아래 유형을 섞는다.

- `echo_twist`: 원문 단어를 비틀어 짧게 받기
- `tiny_objection`: 한 부분만 살짝 반박하기
- `detail_add`: 숫자, 시간, 장면 하나 보태기
- `dry_joke`: 과장 없이 작은 농담 붙이기
- `consequence`: 그래서 생길 결과 한 줄 던지기
- `comparison`: 비슷한 장면과 짧게 비교하기
- `low_agree`: 동의하지만 힘을 빼고 받기

## 밀도 제어

- 댓글 게시글 비율이 낮으면 댓글 후보를 비워두는 것이 정상이다.
- 댓글 평균 길이가 짧으면 한 문장만 허용한다.
- 기존 댓글이 두 줄 이상일 때만 두 줄 댓글을 허용한다.
- 한 배치 안에서 같은 시작어와 같은 어미를 2회 이상 반복하지 않는다.

## 자연스러움 규칙

- 단어 뜻을 묻는 뉴비형 댓글을 기본값에서 제외한다.
- 게시판 전체를 평가하지 않는다.
- 대상 글의 민감 표현을 그대로 재현하지 않는다.
- 댓글은 본문보다 더 짧고 덜 결론적이어야 한다.
- 물음표가 필요한 의문형 어미는 반드시 `?`로 끝낸다.

## 구현 단계

1. 수집 세트에서 댓글 밀도와 평균 길이를 계산한다.
2. 대상 글별 댓글 타깃 점수를 계산한다.
3. 댓글 발화 팔레트를 페르소나와 분리해 별도 선택한다.
4. 생성 프롬프트에 댓글 밀도 규칙과 타깃 훅을 주입한다.
5. 검증 단계에서 댓글-대상 글 연결성, 반복 시작어, 뉴비형 질문을 검사한다.
6. 검토 패키지에 댓글 후보의 타깃 글, 선택 이유, 탈락 이유를 함께 노출한다.

## 성공 기준

- 댓글 없는 글에는 무리하게 댓글을 붙이지 않는다.
- 댓글이 대상 글의 특정 단어나 장면에 바로 붙어 보인다.
- 같은 배치에서 “왜/뭐임/이거”형 확인 댓글이 줄어든다.
- 사용자는 검토 패키지만 보고 댓글이 왜 붙었는지 이해할 수 있다.
