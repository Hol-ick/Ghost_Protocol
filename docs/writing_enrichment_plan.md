# Ghost Protocol 작문 풍성화 기획서

작성일: 2026-06-14

## 목표

현재 작문 품질의 핵심 과제는 특정 갤러리 ID를 하드코딩하지 않으면서도, 각 게시판의 실제 글 목록에서 보이는 소재 폭, 문장 길이, 말끝, 댓글 연결 방식을 자연스럽게 반영하는 것이다. 앞으로의 개선은 “갤러리별 예외 추가”가 아니라 “수집 데이터에서 관측한 신호를 작문 제약으로 변환”하는 방향으로 진행한다.

## 원칙

- 갤러리 ID는 분야 추론의 힌트로만 사용한다. `universe` 같은 정확 ID 전용 프롬프트나 few-shot은 추가하지 않는다.
- 게시판 이름이나 본래 주제를 원고에 직접 설명하지 않는다. 분야 소재가 필요하면 실제 수집 글 또는 분야별 상시 각도의 구체 대상 하나만 쓴다.
- 짧은 제목 목록형 게시판에서는 제목이 본문 역할을 한다. 본문은 비우거나 낮은 후속 체감 한 줄로 제한한다.
- 민감하거나 자극적인 원문은 도덕적 평론으로 바꾸지 않는다. 안전한 숫자, 물건, 화면 장면, 댓글 반응으로 낮춘다.
- 리허설은 단순 반복 생성이 아니라 “다음 사이클에서 무엇이 수렴/탈선/반복되는지”를 측정하는 품질 루프다.

## 데이터 레이어

1. 원본 세트 확장

- 게시글 제목, 본문, 댓글을 하나의 세트로 보존한다.
- 제목만 있는 글과 본문이 있는 글의 비율을 따로 기록한다.
- 댓글은 상위 글 ID와 함께 저장해 댓글 후보가 엉뚱한 소재에 붙지 않도록 한다.
- 글 작성 시간 간격, 추천/댓글 수, 작성자 패턴을 작문량과 발행 간격 판단에만 사용한다.

2. 문체 프로필

- 평균 제목 길이, 본문 길이, 질문형 비율, 웃음 꼬리 비율, 줄임말 비율, `<<`, `<-` 같은 표면 리듬을 산출한다.
- 자주 쓰이는 어미를 수집하되, 모든 글에 반복 적용하지 않는다.
- “짧은 제목형”, “제목+한 줄 본문형”, “본문 설명형”을 자동 분류해 원고 구조를 바꾼다.

3. 분야 추론

- `gallery_purposes.json`의 `id_tokens`, `name_tokens`로 기본 분야를 추론한다.
- 기본 분야는 전체 배치의 낮은 비율만 차지한다.
- 기본 분야 소재는 실제 원본에 있으면 그 원본을 우선하고, 없으면 fallback 각도 중 하나만 조용히 쓴다.

## 작문 레이어

1. 소재 슬롯

- `A/B/C`: 브리핑 핵심 소재
- `R`: 실제 최근 원본 글 하나를 독립 소재로 사용
- `G`: ID/name 토큰으로 추론한 기본 분야 소재
- `F`: 낮은 긴장도의 filler 소재. 음식, 시간, 숫자, 화면 장면처럼 안전하고 짧은 소재만 허용

2. 배치 배분

- 한 배치 안에서 같은 사건군은 최대 2회까지만 허용한다.
- `G` 슬롯은 10개 기준 1개, 20개 기준 2개 정도로 제한한다.
- 민감 소재 실패가 2회 이상 나오면 같은 소재를 반박하지 말고 `R/G/F`로 이동한다.
- 중복 제목은 명사만 바꾸는 방식이 아니라 발화 행동 자체를 바꾼다.

3. 발화 행동 팔레트

- 장면 붙이기: 화면, 숫자, 댓글, 시간 중 하나를 짚는다.
- 디테일 보태기: 이미 나온 주장에 작은 근거 하나를 붙인다.
- 낮은 농담: 과장 없이 짧은 웃음 꼬리만 둔다.
- 생활 연결: 입력에 있는 소재를 비용, 귀찮음, 시간, 선택 문제로 낮춘다.
- 가능성 남기기: 결론을 확정하지 않고 한 단계 뒤를 본다.
- 반대 의견: 도덕적 지적이 아니라 수치나 결과 하나로 낮게 비튼다.

4. 피해야 할 골격

- `왜 자꾸`, `언제부터`, `무슨 뜻`, `기준이 뭐임`, `이건 좀`, `위험하지 않나`, `피곤함`
- 추상 라벨 나열형 제목: `사회 현상`, `논란`, `비판`, `일반화`, `책임론`
- 제목과 본문이 같은 말을 반복하는 구조
- 본문이 브리핑 문장처럼 길어지는 구조

## 검증 레이어

1. 자연스러움 점검

- 제목이 질문형이면 반드시 `?`를 붙인다.
- 질문이 필요 없으면 평서형 장면 반응으로 바꾼다.
- `아님`, `맞냐`, `있나`, `않나`, `건가` 같은 어미는 질문 여부를 감지한다.
- 제목이 조건절에서 멈추면 짧은 결론까지 닫는다.

2. 다양성 점검

- 핵심 명사 HHI와 발화 행동 HHI를 함께 측정한다.
- 같은 소재가 반복되어도 발화 행동이 다르면 일부 허용하지만, 같은 골격 반복은 실패로 본다.
- 실패 사유가 안전 필터인지 중복 필터인지 분리해 리필 전략을 다르게 적용한다.

3. 리필 전략

- 중복 실패: 같은 슬롯 안에서 다른 원본 세트로 이동한다.
- 안전 실패: 민감 표현을 반박하지 말고 안전한 사물·숫자·장면으로 축소한다.
- 소재 부족: `R/G/F` 순서로 낮은 긴장도의 독립 소재를 사용한다.

## 리허설 레이어

1. 사이클 출력

- 각 사이클마다 10개 원고를 성공/실패 포함 목록으로 그대로 보여준다.
- 다음 사이클 브리핑, 작문 지시, 반복 경향, 실패 사유 Top N을 함께 출력한다.
- 주제가 어떻게 수렴하거나 탈선했는지 한 줄 진단을 남긴다.

2. 리허설 메트릭

- 생성 성공률
- 중복 실패율
- 안전 실패율
- 기본 분야 슬롯 비율
- 질문형 제목 비율
- 제목/본문 반복 비율
- 추상 라벨 제목 비율

3. 통과 기준

- 10개 기준 성공 8개 이상
- 동일 사건군 3회 이하
- 질문형 제목 35% 이하
- 브리핑 어휘 직접 노출 0개
- 기본 분야 슬롯 1~2개

## UI 기획

- “문체 프로필 보기” 패널에 제목 길이, 웃음 비율, 질문 비율, 상위 어미를 표시한다.
- “원고만 복사”에는 성공/실패 원고와 실패 사유를 모두 포함한다.
- 리허설 결과 복사는 사이클별 10개 목록, 다음 주제, 다음 작문지시, 실패 사유를 포함한다.
- 운영 리포트에는 누적 로그, 리필 횟수, 성공률, 현재 모드, 최근 사이클을 함께 표시한다.

## 단계별 구현안

1. 정적 갤러리 컨텍스트 축소

- 새 갤러리 ID는 `gallery_contexts.json`에 추가하지 않는다.
- 분야 추론은 `gallery_purposes.json`으로만 확장한다.
- 문체는 수집 원본 기반 `gallery_style`이 담당한다.

2. 원고 구조 풍성화

- 본문 길이를 단일 규칙이 아니라 게시판의 원본 구조에 맞춰 선택한다.
- 댓글 초안은 대상 글의 제목/본문/댓글 세트와 같은 소재일 때만 만든다.
- 실패 후보도 보존해 다음 프롬프트 개선 데이터로 사용한다.

3. 리허설 강화

- 사이클별 수렴 주제와 작문 지시를 명시적으로 저장한다.
- 반복되는 실패 골격을 자동 금지어가 아니라 “다음 슬롯 이동” 신호로 사용한다.
- 리허설 종료 시 품질 리포트를 자동 생성한다.

4. 장기 개선

- 갤러리별 하드코딩 대신 분야별 토큰 사전을 확장한다.
- 사용자 검토에서 “어색함”으로 표시한 원고를 negative example로 저장한다.
- 좋은 원고는 문장 자체가 아니라 구조 특징만 추출해 재사용한다.
