# Ghost Protocol Studio 재설계

2026-09-06 · 로컬 편집 스튜디오 구현 / 외부 자동 운영은 보존된 콘솔로 분리

## 목표와 결정

여러 차례 추가된 실행·실험·로그·설정을 원고 작업 흐름으로 재정리했다. 화면을 꾸미는 변경에 그치지 않고 작업 상태와 실행을 UI에서 분리했다. 기존 Python/Streamlit과 GeminiClient/GhostBrain/보호 수집기를 재사용한다. 새 외부 라이브러리나 클라우드 서비스는 추가하지 않았다. Streamlit 최소 버전은 현재 검증한 1.54다.

- 기본 모델: 사용자 선택에 따라 `gemini-3.1-flash-lite`. 비교 후보: `gemini-2.5-flash`.
- 원본 페르소나와 전체 작문 템플릿 보존. 추가 규칙만 별도 저장한다.
- 정상 자료와 확인된 분석이 있어야 생성한다. 파싱 실패 시 다음 원고를 만들지 않는다.
- 모델이 임의 생성한 대상 댓글은 원본 응답에 남기고 승인 패키지에서는 제거한다.
- 사실성은 휴리스틱 경고와 사람 검토의 대상이며 자동 품질 보증으로 취급하지 않는다.
- 새 작업실은 원고 승인·내보내기까지 담당한다. 계정 로그인·자동 게시·무한 실행은 연결하지 않는다.

## 정보 구조

| 공간 | 제공 기능 | 상태·실패 처리 |
|---|---|---|
| 작업실 | 작업 생성·선택, 직접 자료, 기존 DB 읽기, 보호 수집, 분석 확인, 생성, 편집, 승인, Markdown/JSON | 빈 자료·차단·파싱 오류·미확인 분석은 다음 실행 금지 |
| 페르소나·규칙 | 원본 프로필·전체 프롬프트 열람, 공통/페르소나별 추가 규칙 저장 | 원본 파일은 변경하지 않고 설정 이력 보존 |
| 실험실 | 기존 10쌍 나란히 비교·20개 원고 가져오기, 새 2모델 비교 | 같은 소재·페르소나·규칙, 최대 모델당 10개, 명시적 API 실행 |
| 운영 기록 | 작업 진행·중단·실패·소요 시간, 호출별 요청/응답/토큰/계산 비용 | 미실행·실패·비용 미확인을 성공/0원으로 대체하지 않음 |
| 설정 | 모델·호출 간격·원고 상한·수집 페이지, 키 존재 확인 | 키 값 노출 없음. 설정됨은 실접속 성공이 아님 |

작업실 순서: **자료 준비 → 분석 확인 → 원고 제작 → 비교·수정 → 게시 승인**.
단계는 탐색할 수 있지만 서비스 계층이 실행 조건을 검사한다.

## 구조와 저장 계약

```text
app.py
 ├─ 기본: studio/ui.py                화면·폼·메뉴·진행 표시
 │         └─ StudioService           명령·선행 조건·직렬 워커·취소·승인
 │              ├─ StudioStore       로컬 SQLite 문서·이력
 │              └─ StudioBackend     기존 Brain / GeminiClient / 보호 수집 / DB 읽기
 └─ ?legacy=1: legacy_app.py          이전 운영 화면 보존
```

저장소는 `data/studio/studio.sqlite3`이며 Git에서 제외한다. 기존 `data/ghost_protocol.db`는 새 스튜디오에서 읽기 전용으로 연다. 문서 종류는 workspace, job, call, settings, source_revision, draft_revision, settings_revision이다. SQLite 연결은 매 작업 후 닫고 WAL과 매개변수 쿼리를 사용한다.

- 화면 새로고침·메뉴 이동은 API/수집 명령을 제출하지 않는다.
- 한 Studio 프로세스 안에서는 작업 하나만 실행한다. 중복 제출·실행 중 원본/원고 변경을 거부한다.
- 중단은 현재 외부 호출이 끝난 뒤 적용되며 이미 받은 원고를 보존한다. 서버 재시작 시 실행 중이던 작업은 interrupted 처리하고 자동 재시도하지 않는다.
- 저장한 원고는 revision을 올리고 이전 승인을 해제한다. 편집·승인 모두 예상 버전을 검사해 다른 탭의 오래된 화면으로 새 버전을 승인하지 못하게 한다.
- 원본 자료를 바꾸면 이전 스냅샷을 보존하고 분석을 비우며, 기존 원고를 이전 자료 기반으로 표시해 승인에서 제외한다.
- 브라우저에서 아직 저장하지 않은 제목/본문은 메뉴 이동 동안만 유지한다. 탭 새로고침·종료 전에는 반드시 저장해야 한다.
- 내보내기에는 현재 승인된 제목·본문·페르소나·버전·승인 시각만 포함한다. 승인 상태는 `approved_not_published`다.

모델별 비교는 동일 소재·페르소나·추가 규칙과 동일한 로컬 난수 seed를 사용한다. 서버 측 모델 난수나 여러 프로세스의 동시 실행까지 동일성을 보장하지 않는다. 실제 전달 프롬프트와 응답은 호출 이력에서 확인한다.

## 디자인 기준

밝은 회색 바탕, 흰 원고, 보라색 편집선으로 원고와 조작부를 구분한다. 상단에는 공간 탐색, 작업 선택, 5단계만 두고 항상 보이던 긴 로그를 분리했다. 데스크톱에서는 원고/근거와 모델별 결과를 나란히, 좁은 화면에서는 세로로 배치한다. 한글 본문 15px 이상, 보조 설명 14px, 보조 문구의 기본 불투명도를 복원했다. 명시적 포커스 테두리와 reduced-motion 규칙을 포함한다.

## 보존·전환 범위

`legacy_app.py`는 기존 대형 app.py의 운영 기능을 보존한다. 무한 실행, 리허설, 자동 게시, 댓글 감시, 기존 보고서 및 계정 작업은 여기서 사용한다. 새 원고 승인이 기존 게시 워커로 자동 전달되지 않는다. 새/기존 콘솔은 큐를 공유하지 않으므로 외부 작업을 동시에 실행하지 않는다. 여러 서버 프로세스가 동일 Studio DB를 공유하는 배포도 지원 범위 밖이다.

기존 prompt 자산·계정·세션·DB·Ollama 설치와 사용자 변경은 제거하지 않았다. 새 스튜디오의 설정은 CLI/기존 콘솔의 `.env` 모델 설정을 덮어쓰지 않는다. 기본 자료·원고 슬롯은 단일 소재 편집용이며 기존 자동 운영의 상시 분야 10% 배치 편성은 기존 콘솔 범위다. 이를 새 단일 소재 생성의 품질 검증으로 오인하지 않는다.

앱 업데이트 후에는 현재 작업을 끝내고 Streamlit 프로세스를 재시작한다. 개발 중 Python 파일만 다시 불러오면 캐시된 이전 서비스 객체가 남을 수 있다. 재설계 검증에서 이 상태를 발견했고 관리 중인 앱을 재시작해 확인했다.

## 운영·개인정보

Streamlit은 127.0.0.1에 바인딩한다. 화면 공유/포트 공개/인터넷 배포를 하지 않는다. Google API 실행 시 선택된 자료와 프롬프트가 외부로 전송된다. API 키는 로컬 환경 파일에 두고 새 DB나 브라우저에 저장하지 않는다. 호출 원문에는 사용자가 넣은 자료가 포함될 수 있으므로 개인 식별 정보는 입력 전에 제외하고 로컬 DB·로그를 공개 저장소에 올리지 않는다.

비용은 사용량과 2026-09-06 일반 유료 단가로 계산하며 청구서 확정액이 아니다. 전송 후 응답 유실 등으로 사용량이 확인되지 않으면 미확인으로 남긴다. 사실 오류, 개인정보, 직접 경험을 꾸미는 표현 등은 게시 전에 사람이 검토해야 한다.

## 후속 변경: 기능 중심 패널

2026-09-06 사용자 요청으로 상시 보조 설명·문장형 페이지 제목·브랜드 부제·저장 위치 안내를 제거했다. 원고/설정 패널은 보조 caption 0개이며 입력·선택·버튼과 실제 작업 데이터만 기본 표시한다. 페르소나 세부 내용과 실험 검증 결과는 접힌 항목으로 옮겼다. 빈 상태는 짧은 상태명으로, 과금·검토 동의와 미저장·실패 경고는 짧은 행동 관련 메시지로 유지했다. 생성·승인·저장 서비스와 원본 데이터는 변경하지 않았다.

- 전체 동작 회귀: 390 passed, 2 skipped / 49.60초. 설명 제거와 과금 동의 유지 UI 테스트 2개 추가.
- 실제 화면: 1280×720 및 390×844, 원고 편집·설정·실험실 확인. 가로 넘침 없음, 브라우저 오류/경고 없음. 키보드 전용 전 흐름은 이번 범위에 포함하지 않았다.
- 추가 시각 수정: Streamlit 폼 저장 버튼의 `primaryFormSubmit` 스타일에도 흰 글자를 적용했다. 브라우저 계산 색상이 `rgb(32, 38, 58)`에서 `rgb(255, 255, 255)`로 바뀐 것을 확인했다.
- 실제 게시판·로그인·게시·유료 API 호출 없이 검증했다. 기존 사용자 변경 `cycle_memory.json`, `API_USAGE.md`는 이번 변경에 포함하지 않았다.
